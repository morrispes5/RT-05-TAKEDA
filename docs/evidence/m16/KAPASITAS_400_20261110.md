## 3. Temuan dan perbaikan

1. **Kunci keuangan eksklusif di layar baca (diperbaiki, PR #125).** `GET /dues/my` dan `/cash/summary` mengambil
   `pg_advisory_xact_lock('rt05:keuangan')` eksklusif: semua pembukaan layar Iuran satu RT antre satu per satu. Dengan
   ±17 query lewat jembatan (koneksi baru ±110 ms + tiap query), satu layar ±0,5 dtk → maksimal ±2 layar Iuran/detik untuk
   seluruh RT, dan antrean memakan slot 20 proses. Kini pembaca memakai kunci bersama (`readLock`), penulis tetap eksklusif.
   Tes `M16FinanceReadLockTest`.
2. **`rt05:demo-seed` rusak (diperbaiki, PR #125)**: pemohon tambahan tanpa nama kepala (M15b), tarif ledger diubah langsung
   (ditolak trigger M18), rumah ADR58 tanpa tagihan. Tes `M16DemoSeedTest`. Hanya alat uji lokal, tidak menyentuh production.
3. **Kuota Neon Free (keputusan pemilik).** Project production: aktif 162.932 dtk (±45 jam × 0,25 CU ≈ 11 CU-jam) sejak
   5 Nov dari kuota 100 CU-jam/bulan. Dengan 400 warga aktif, compute bisa bangun hampir sepanjang hari
   (±16–20 jam × 0,25 CU × 30 ≈ 120–150 CU-jam) → **melewati kuota gratis**; compute disuspend sampai bulan berikut.
   Pantau mingguan; opsi: paket Neon berbayar atau pindah ke cadangan (ADR29/39).
4. **Anti-bot hosting per IP (keputusan pemilik / tiket Biznet).** Setelah ±150 permintaan cepat dari PC operator
   (smoke + ukur latensi), IP rumah pemilik (tanpa WARP) mendapat `403` + halaman "One moment, please…" (openresty) untuk
   website **dan** API; dari IP lain tetap 200. Aplikasi Android tidak bisa menjalankan tantangan JavaScript, jadi HP di
   Wi-Fi yang sama ikut gagal selama blokir. Risiko 400 warga: banyak HP di balik NAT operator seluler/RT yang sama
   bisa memicu blokir yang sama saat alarm/pengumuman. Usul tiket Biznet: kecualikan `/api/`, `/unduh/`, `/up` dari
   tantangan bot atau naikkan ambang. **Jangan uji beban production dari satu IP.**
5. Kosmetik (tahap evaluasi): tombol "Detail" kartu Iuran Beranda tampil di tengah, bukan kanan; teks Lupa kata sandi masih
   teknis ("Server mengantrekan email reset…").

## 4. Model kapasitas production (perkiraan, bukan uji beban live)

Per request: bootstrap PHP ±20–30 ms CPU + koneksi WebSocket baru ke Neon ±110 ms (ADR55) + ±15–60 ms per query.
Layar warga rata-rata ±8 query → ±0,3–0,6 dtk; membuka aplikasi ±8 request. Throughput dibatasi CPU 1 inti
(±35–45 request/dtk) dan 20 proses bersamaan (±40–60 request/dtk).

| Skenario 400 warga | Beban | Status |
